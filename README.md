# NAWA Tracker

Polish-first scholarship questionnaire and community statistics by country, delivered as a **Telegram Mini App**. One Telegram account maps to one applicant profile. The browser talks only to same-origin Vercel Functions; Supabase is accessed server-side with a service-role credential.

Architecture details live in [`docs/architecture.md`](docs/architecture.md). Product intent, questionnaire flow, and Anders 13/2026 mapping live in [`docs/product-flow.md`](docs/product-flow.md). How to test each layer is in [`docs/testing.md`](docs/testing.md).

Only the **NAWA Director** scholarship is live: the Health and Culture minister tracks are hidden until their scoring documents are modelled (the enum values and database constraints stay in place). Records are keyed by `(Telegram account, intake year)`. The app asks only for the countries and the grades, because the point is to show where a score stands among other applicants. Fields it no longer asks for (university, field of study, study route, application status) keep their columns and are sent as neutral defaults; see [ADR 0008](docs/adr/0008-refocus-on-score-comparison.md).

Statistics compare the NAWA orientation score only with the valid surveys of the applicant's **country of citizenship** on the same track and intake. There is no minimum number of responses: the full position (rank, percentile, median, distribution) appears from two surveys in the country, which is shown next to it, and a single "only you" line appears below the score while the country has fewer. Country groups and the whole-track fallback are no longer used ([ADR 0015](docs/adr/0015-compare-within-citizenship-country-without-minimum.md)). Aggregates are never an official ranking or seat-limit forecast.

### Languages

Polish, English, Russian, Ukrainian, and Belarusian (official orthography). The interface starts in the stored choice, then the Telegram language, then the browser language. The Ukrainian and Belarusian texts are drafts that still need a native-speaker review.

### Not asked at the start

The first screen asks for the country of citizenship, the school country and the grades. The target university and field of study are not asked; a later, separate flow for people who received a scholarship will ask where they wanted to go and where they were placed. The catalogue of NAWA partner universities (`shared/universities*.ts`, `shared/university-search/`) and the ISCED-F field list (`shared/study-fields.ts`) stay in the repository for that flow.

## Requirements

- Node.js 20.19 or newer (or 22.12 or newer) and npm
- A Supabase project (remote) **or** Docker Desktop for local Supabase
- A Telegram bot created via [BotFather](https://t.me/BotFather)
- A Vercel account; the Vercel CLI is not a project dependency (it is ~100 MB of `node_modules`), run it on demand as `npx vercel@45 <command>`

## Environment

Copy `.env.example` to `.env.local` and set these values:

| Variable | Scope | Purpose |
| --- | --- | --- |
| `VITE_TELEGRAM_DEV_INIT_DATA` | Browser | Optional signed initData for local browser testing outside Telegram WebView. Generated by `npm run local:env`. |
| `VITE_TELEGRAM_BOT_USERNAME` | Browser | Public bot username (without `@`) used for the gate screen, the reminder link and the country invitation links. Defaults to `nawa_tracker_bot`. |
| `VITE_SUPPORT_TELEGRAM_USERNAME` | Browser | Optional chat that receives support messages; defaults to the bot username. |
| `TELEGRAM_BOT_TOKEN` | Server | Bot token from BotFather; used to verify Mini App `initData` HMAC. Minimum 32 characters. |
| `SUPABASE_URL` | Server | Supabase project URL. |
| `SUPABASE_SERVICE_ROLE_KEY` | Server | Supabase secret/service-role key used only by Vercel Functions. |
| `IDENTITY_PEPPER` | Server | Secret pepper for the pseudonymous account key (HMAC-SHA256 of the Telegram id). Minimum 32 characters; generate with `openssl rand -base64 32`. Changing it orphans every stored profile. |
| `APP_PUBLIC_URL` | Server | Exact HTTPS origin of the Mini App used for Origin checks. |
| `TELEGRAM_WEBHOOK_SECRET` | Server | Secret Telegram echoes back in `X-Telegram-Bot-Api-Secret-Token` on every webhook call; minimum 32 characters. Without it `POST /api/bot` answers 503. |
| `CRON_SECRET` | Server (production) | Secret for Vercel Cron auth on `/api/cron/keep-alive` and `/api/cron/reminders`; minimum 32 characters. Generate with `openssl rand -base64 32`. |
| `DATABASE_URL` | Tests only | PostgreSQL connection string for an isolated, migrated test project. |

All variables except the three `VITE_*` ones are server-only. Never prefix a secret with `VITE_`, expose `SUPABASE_SERVICE_ROLE_KEY` to the browser, or add real values to tracked files.

For production, set `APP_PUBLIC_URL` to the exact HTTPS origin with no path, query, fragment, or trailing slash.

## Telegram Bot setup

1. Create a bot with BotFather (`/newbot`).
2. Set the Mini App URL to your deployed `APP_PUBLIC_URL` (`/setmenubutton` or Bot Settings → Menu Button).
3. Copy the bot token into `TELEGRAM_BOT_TOKEN` on Vercel.
4. Users open the tracker from Telegram; the WebView supplies signed `initData` on every API call.

### Bot commands, reminders and country links

The bot answers `/start`, `/subscribe`, `/stop` and `/help` through `POST /api/bot`, and a daily cron (`/api/cron/reminders`) sends the reminders implied by `shared/season.ts` to people who subscribed.

1. Set `TELEGRAM_WEBHOOK_SECRET` (and `CRON_SECRET`) on Vercel, deploy, then register the webhook once:

   ```bash
   curl -sS "https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/setWebhook" \
     --data-urlencode "url=$APP_PUBLIC_URL/api/bot" \
     --data-urlencode "secret_token=$TELEGRAM_WEBHOOK_SECRET" \
     --data-urlencode 'allowed_updates=["message","my_chat_member"]'
   ```

2. In BotFather set the commands (`/setcommands`): `start`, `subscribe`, `stop`, `help`.
3. For `https://t.me/<bot>?startapp=c_UA` country links, configure the bot's **Main Mini App** (BotFather → Bot Settings → Configure Mini App) with the same URL. The bot's own inline button uses `?c=UA` and needs no extra setup.
4. Vercel Hobby runs cron at most once a day, which is all the reminders need. The handler sends up to 200 messages per run and drops subscribers who blocked the bot.

Privacy: `bot_subscriptions` is the only table with a real Telegram id. Rows exist only after `/subscribe`, and disappear on `/stop`, when the bot is blocked, and when the survey is deleted in Settings.

## Supabase Setup

Create a new Supabase project and apply the tracked migration:

```bash
npx supabase@latest login
npx supabase@latest link --project-ref YOUR_PROJECT_REF
npx supabase@latest db push
```

`db push` applies all migrations in `supabase/migrations/`. Do not edit production tables manually outside migration history.

Verify RLS in the SQL Editor — `responses` and `submission_limits` should have RLS enabled, zero policies, and no `anon`/`authenticated` table access.

## Local Development

### Option A — Local Supabase in Docker (seeded mock data)

```bash
npm install
npm run db:start
npm run local:env
npm run local:dev
```

`npm run local:env` writes `.env.local` with local Supabase credentials, a fixed dev bot token, and `VITE_TELEGRAM_DEV_INIT_DATA` for user `900000001` (seeded demo profile). Open `http://localhost:3000` in a browser for UI work.

### Option B — Remote development project

```bash
npm install
npm run local:dev
```

Use `npx vercel@45 link` and `npx vercel@45 env pull .env.local` if the project environment is managed by Vercel.

## Vercel Deployment

1. Link the project with `npx vercel@45 link`.
2. Set framework preset to Vite, build `npm run build`, output `dist` (`vercel.json` tracks these).
3. Add `TELEGRAM_BOT_TOKEN`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `IDENTITY_PEPPER`, `TELEGRAM_WEBHOOK_SECRET`, `CRON_SECRET`, and `APP_PUBLIC_URL` to Production.
4. Deploy with `npx vercel@45 --prod`.
5. Point the bot Menu Button to the production `APP_PUBLIC_URL`.
6. Test create, update, statistics, and profile-exists conflict from Telegram.

`vercel.json` allows Telegram embedding via CSP `frame-ancestors` and removes `X-Frame-Options: DENY`.

## Privacy And Limits

The app stores questionnaire answers under a **pseudonymous account key** (an HMAC of the Telegram id; the database never holds the id or username). It does not store name, email, phone or search queries. Everything shown to other users is aggregate: the position is computed only within the applicant's country of citizenship, and outcome scores appear in 5-point bands. This is pseudonymous, not anonymous: in a country with few responses, acquaintances can guess whose score is whose. The one exception is the opt-in bot reminders: after `/subscribe` the bot keeps your Telegram id in a separate table until `/stop`, a blocked bot, or deleting your survey. Deleting a profile in Settings removes all of its intake years. Percentile statistics use every valid, non-suspicious response of the applicant's country of citizenship on the same track and intake; there is no minimum, and with fewer than two responses the card shows only the score and a line naming the country. Outcome score ranges are disclosed from three awarded responses and rounded to 5-point bands. Opening the hosted URL outside Telegram shows a gate screen; the API requires valid signed `initData`.
