# NAWA Tracker

Polish-first scholarship questionnaire and privacy-safe community statistics by passport country, delivered as a **Telegram Mini App**. One Telegram account maps to one applicant profile. The browser talks only to same-origin Vercel Functions; Supabase is accessed server-side with a service-role credential.

Architecture details live in [`docs/architecture.md`](docs/architecture.md).

The active questionnaire scope is fixed to three programme tracks (`nawa_director`, `health_minister`, `culture_minister`), two study routes (`preparatory_course`, `direct_studies`), and ten application statuses from `submitted` through `scholarship_awarded` / `scholarship_not_awarded`.

Statistics compare declared grades (or the NAWA orientation score for `nawa_director`) within the same scholarship track and ranking citizenship country, with a track-wide fallback when a country cohort is too small. Aggregates are never an official ranking or seat-limit forecast.

## Requirements

- Node.js 20.19 or newer (or 22.12 or newer) and npm
- A Supabase project (remote) **or** Docker Desktop for local Supabase
- A Telegram bot created via [BotFather](https://t.me/BotFather)
- A Vercel account; the lockfile-pinned local Vercel CLI is invoked through `npx vercel`

## Environment

Copy `.env.example` to `.env.local` and set these values:

| Variable | Scope | Purpose |
| --- | --- | --- |
| `VITE_TELEGRAM_DEV_INIT_DATA` | Browser | Optional signed initData for local browser testing outside Telegram WebView. Generated by `npm run local:env`. |
| `TELEGRAM_BOT_TOKEN` | Server | Bot token from BotFather; used to verify Mini App `initData` HMAC. Minimum 32 characters. |
| `SUPABASE_URL` | Server | Supabase project URL. |
| `SUPABASE_SERVICE_ROLE_KEY` | Server | Supabase secret/service-role key used only by Vercel Functions. |
| `IP_HASH_SALT` | Server | Independent secret for transient IP HMACs on public statistics rate limits. Minimum 32 characters. |
| `APP_PUBLIC_URL` | Server | Exact HTTPS origin of the Mini App used for Origin checks. |
| `DATABASE_URL` | Tests only | PostgreSQL connection string for an isolated, migrated test project. |

All variables except `VITE_TELEGRAM_DEV_INIT_DATA` are server-only. Never prefix a secret with `VITE_`, expose `SUPABASE_SERVICE_ROLE_KEY` to the browser, or add real values to tracked files.

For production, set `APP_PUBLIC_URL` to the exact HTTPS origin with no path, query, fragment, or trailing slash.

## Telegram Bot setup

1. Create a bot with BotFather (`/newbot`).
2. Set the Mini App URL to your deployed `APP_PUBLIC_URL` (`/setmenubutton` or Bot Settings → Menu Button).
3. Copy the bot token into `TELEGRAM_BOT_TOKEN` on Vercel.
4. Users open the tracker from Telegram; the WebView supplies signed `initData` on every API call.

## Supabase Setup

Create a new Supabase project and apply the tracked migration:

```bash
npx supabase@latest login
npx supabase@latest link --project-ref YOUR_PROJECT_REF
npx supabase@latest db push
```

`db push` applies `supabase/migrations/202607130001_initial_schema.sql`. Do not edit production tables manually outside migration history.

Verify RLS in the SQL Editor — `responses` and `submission_limits` should have RLS enabled, zero policies, and no `anon`/`authenticated` table access.

## Local Development

### Option A — Local Supabase in Docker (seeded mock data)

```bash
npm install
npm run db:start
npm run local:env
npm run local:dev
```

`npm run local:env` writes `.env.local` with local Supabase credentials, a fixed dev bot token, and `VITE_TELEGRAM_DEV_INIT_DATA` for user `900000001` (seeded demo profile). Open `http://localhost:3000` in a browser for UI work.

### Option B — Remote development project

```bash
npm install
npm run local:dev
```

Use `npx vercel link` and `npx vercel env pull .env.local` if the project environment is managed by Vercel.

## Vercel Deployment

1. Link the project with `npx vercel link`.
2. Set framework preset to Vite, build `npm run build`, output `dist` (`vercel.json` tracks these).
3. Add `TELEGRAM_BOT_TOKEN`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `IP_HASH_SALT`, and `APP_PUBLIC_URL` to Production.
4. Deploy with `npx vercel --prod`.
5. Point the bot Menu Button to the production `APP_PUBLIC_URL`.
6. Test create, update, statistics, and profile-exists conflict from Telegram.

`vercel.json` allows Telegram embedding via CSP `frame-ancestors` and removes `X-Frame-Options: DENY`.

## Privacy And Limits

The app stores questionnaire data and the Telegram user identifier (`telegram_user_id`, optional `telegram_username`). It does not collect email, phone, or legal name. Aggregate statistics suppress detailed groups below ten valid, non-suspicious responses. Opening the hosted URL outside Telegram shows a gate screen; the API requires valid signed `initData`.
